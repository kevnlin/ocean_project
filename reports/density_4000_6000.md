## 2. The curve is not a power law

A single fit over N ∈ [100, 3000] gives

$$\mathrm{RMSE}_{\text{TEMP}} = 1.041 \, N^{-0.269}, \qquad R^2_{\log\log} = 0.963$$

That $R^2$ looks reassuring and is misleading. The residuals are **systematic**,
not random (−7.4 %, +5.5 %, +6.8 %, +2.1 %, −8.0 %): the fit sits above the data
in the middle and below it at both ends, which is the signature of a slope that
is changing. Segment-wise slopes confirm it:

| segment | local α |
|---|---:|
| 100 → 300 | 0.151 |
| 300 → 750 | 0.254 |
| 750 → 1500 | 0.340 |
| **1500 → 3000** | **0.410** |

α rises monotonically. The plan's α = 0.41 is exactly the **last segment**, not
the curve.

**Why the slope steepens.** At N → 0 the RMSE cannot exceed the
no-observation limit (0.2983 °C at N = 0), so the curve must flatten at low
density — a few profiles spaced far beyond the background-error correlation
length constrain almost nothing, and the reconstruction falls back on the
prior. As density crosses that threshold, each profile starts to carry real
information and returns *accelerate*. This is a saturation effect at the low
end, not a physical law that can continue: at high enough N the curve must
flatten again against an irreducible error (unresolved sub-grid variability,
the 1° grid itself). So the tail slope is an **optimistic** extrapolant and the
global fit a **conservative** one.

## 3. The answer, with its uncertainty stated

| model | 4000 | 6000 | N at 0.1 °C |
|---|---|---|---|
| global fit (α = 0.269) — conservative | 0.1122 | 0.1006 | **6143** |
| tail slope (α = 0.410) — optimistic, = the plan's | 0.0997 | 0.0844 | **3973** |

**Both are extrapolations beyond the measured range**, and they disagree by
~55 % on the crossing point (≈4000 vs ≈6100 profiles/month). Neither should be
quoted as *the* answer.

> **The honest answer for the advisor**: TEMP crosses 0.1 °C somewhere between
> **~4000 and ~6100 profiles/month**, and the spread is dominated by whether the
> observed acceleration in returns continues or flattens. That ambiguity is
> precisely what the 4000/6000 runs resolve — which is the argument for running
> them, rather than a reason to quote a number from either curve now.

## 4. Reality anchor

The real Argo array is ~4000 active floats delivering ~12 000 profiles/month
globally, but **spatially very uneven** — dense in the North Atlantic and
Southern Ocean, sparse in the tropics, marginal seas and under ice. Our
synthetic sampling is uniform-random over the ocean mask, so "N = 4000
uniform" is a *more evenly informative* array than 4000 real floats, while
"12 000 real profiles" is less informative per profile than 12 000 uniform ones.
The two numbers are not directly comparable, and the report should not imply
that real Argo already sits at the right-hand end of this curve.

## 5. How to finish this (needs one free GPU)

The week-2 script writes to a **fixed** cache path, so a naive extension run
would overwrite committed results. That footgun is now removed —
`08_density_ablation.py` takes `--out-suffix` (default empty = unchanged
behaviour):

```bash
# one seed per free card; check nvidia-smi first
CUDA_VISIBLE_DEVICES=N python experiments/08_density_ablation.py \
    --seed 1234 --densities 4000,6000 --out-suffix _ext
# then fold into the main curve (idempotent, refuses incomparable run_configs,
# writes *.bak_premerge on first touch)
python experiments/merge_density_json.py --seeds 1234 --dry-run
python experiments/merge_density_json.py --seeds 1234
python experiments/31_density_powerlaw.py          # re-fit with measurements
```

Repeat for seeds 1235/1236 for the 3-seed headline. Budget roughly half a day
per seed on one card (two densities × every method retrained).

When the measurements land, §3's two-model table collapses to one measured row
and this report should state the crossing as a measurement, not an
extrapolation.
